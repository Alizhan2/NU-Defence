# Data card

Целевой источник — DOTA; xView допустим как fallback. MVP-таксономия: aircraft, ship, small vehicle, large vehicle; она не является окончательной таксономией заказчика. Сплиты должны формироваться по исходной сцене до тайлинга, чтобы фрагменты одной сцены не попали в разные splits. Test не участвует в обучении или подборе threshold.

Проверки: лицензия и provenance, SHA-256 manifest, bbox внутри изображения, согласованность label map, пустые/дублирующиеся аннотации, баланс классов, распределения GSD/облачности/угла. Augmentation применяется только к train. `data/demo` — synthetic plumbing sample, не evidence качества.

## Текущее доказанное состояние

Локальный `data/dota8_stage2` содержит 3 train, 4 val и 1 test изображения. Все
четыре val-аннотации пусты, а test содержит только один экземпляр `aircraft`.
Поэтому набор годится только для проверки plumbing, но не для независимой оценки
четырёх классов. Числа из `runs/metrics_test.json` нельзя связать с этим локальным
test split: в файле отсутствуют `split=test` и fingerprint датасета.
Пустой validation split также не позволяет воспроизвести выбор модели или порога.

Воспроизводимая проверка:

```powershell
python scripts/audit_model.py
```

Она проверяет утечки исходных сцен, совпадающее содержимое между splits,
структуру аннотаций, coverage классов, происхождение метрик и три отдельных
состояния checkpoint: файл найден, модель загрузилась, probe inference выполнен.
